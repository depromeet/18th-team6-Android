# Clear with Lessons (세션 종료 + 교훈 저장)

세션을 종료하기 전에, 이번 세션에서 의미 있는 교훈이 있으면 저장한다.

## 실행 단계

### 1단계: 세션 회고

이번 세션 전체를 회고하여 아래 항목을 정리한다.

#### A. 실패한 시도 (가장 중요)
- 무엇을 시도했고, 왜 실패했는지 기록
- 원인이 확실하지 않으면 반드시 **(추정)** 을 붙일 것
- 예: `gcloud triggers create --repo-name → INVALID_ARGUMENT (추정: 2세대 연결에서는 --repository 필수)`

#### B. 실패에 대한 대처와 결과
- 각 실패에 어떻게 대처했는지 기록
- 대처가 또 실패한 경우, 그 이유도 명시
- **미봉책으로 처리한 경우 반드시 명시** (예: "근본 해결 아닌 우회 — 추후 재검토 필요")

#### C. 사용자 추가 조치 필요 항목
- 사용자가 직접 수행해야 할 작업이 남아 있으면 정리
- `docs/request.md` 파일의 **최상단**에 추가 (기존 내용 아래로 밀어냄, 현재 프로젝트 루트 기준)
- 형식:
  ```
  ## [날짜] 세션 요약 (한 줄)

  - [ ] 조치 항목 1
  - [ ] 조치 항목 2
  ```
- 사용자 조치가 없으면 이 단계는 건너뛴다

### 2단계: 교훈 저장 판단

**교훈이 저장할 가치가 있는지 판단한다.** 아래 기준에 해당하는 것만 저장한다:

- 실패 → 원인 분석 → 해결까지의 과정에서 얻은 비자명한 인사이트
- 반복될 가능성이 높은 실수나 함정
- 문서화되어 있지 않은 도구/API/프레임워크의 동작 방식 발견
- 아키텍처 또는 설계 결정에 영향을 주는 발견

**저장하지 않는 것:**
- 단순한 작업 기록 (파일 수정, 문서 작성 등)
- 당연한 사실의 확인
- 교훈이랄 것 없는 순조로운 세션

교훈이 없으면 **"이번 세션에서 특별한 교훈은 없습니다."** 라고만 보고하고 바로 3단계로 넘어간다.

교훈이 있으면 `docs/insights/` 디렉토리에 `YYYY-MM-DD_주제.md` 형식으로 저장한다.

### 3단계: 보고 및 종료

교훈 유무와 관계없이, 세션 요약을 간결하게 보고한 뒤 사용자에게 `/clear`를 실행하라고 안내한다.

## 주의사항

- **MEMORY.md는 이 스킬에서 업데이트하지 않는다.** auto memory 시스템이 별도로 관리한다.

## 모델 선택 가이드

- 전 과정: `sonnet` (회고 + 파일 쓰기)

## 품질 체크리스트

- [ ] 실패한 시도가 빠짐없이 기록되었는가?
- [ ] 원인 불확실한 경우 (추정) 표시가 있는가?
- [ ] 미봉책에 명시적 표시가 있는가?
- [ ] 교훈 저장 기준을 충족하는 항목만 저장했는가?
- [ ] 사용자 조치 항목이 있으면 docs/request.md에 추가했는가?
